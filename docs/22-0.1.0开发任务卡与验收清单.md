### P1-1 · `Problem` 错误码基础设施（0.5 人日）

**目标**：所有失败都有一个稳定编号，UI 不再拼接中文字符串，日志可按码检索。

> 为什么只要 0.5 人日：约 45 条错误码在 19 号 §2 已经定义完毕，这里是把表格转成常量，属抄录工作，不是设计工作。

**改动文件**
- 新增 `linguaforge/core/problems.py`
- 修改 `linguaforge/core/__init__.py` 导出

**结构**（与 19 号 §2 的错误码表一一对应）
```python
class Severity(str, Enum):
    FATAL = "fatal"  # 任务终止
    PAGE = "page"  # 单页失败，任务继续
    BLOCK = "block"  # 单块失败，保留原文
    WARN = "warn"  # 可继续但需提示


@dataclass(frozen=True)
class Problem:
    code: str  # 如 "LF-PDF-1003"
    severity: Severity
    params: dict = field(default_factory=dict)
    detail: str = ""  # 仅进日志，不进 UI
    page: int | None = None
```
**约束**：`problems.py` 只放常量与数据结构，**不 import 任何业务模块**（避免循环依赖）。

**验收命令**
```
python -c "from linguaforge.core.problems import Problem, Severity; print(Problem('LF-PDF-1003', Severity.FATAL))"
pytest -q tests/test_core.py
```
**DoD**：错误码常量化；`Problem` 可被 `dataclasses.asdict` 序列化；新文件无第三方依赖。
