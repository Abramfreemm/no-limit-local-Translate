## 0. 本文档的定位

`02` 是 **SRS（系统需求）**：用 `FR-x.y` 编号描述"系统必须具备哪些能力"，读者是开发和测试。
本文档是 **PRD（产品需求）**：描述"用户在什么场景下、按什么顺序、看到什么、点哪里、失败时看到什么"，读者是设计、开发、测试与文档写作。

**两者不是替代关系，变更含义不同**：

| 文档 | 变更意味着 | 审批人 |
|---|---|---|
| 02 SRS | 范围变了，工期与验收标准要改 | 产品决策 |
| 13 PRD | 体验变了，交互与文案要改，范围不变 | 产品 + 设计 |

一条判断规则：**如果改动不影响"能做/不能做"，只影响"好不好用"，改本文档；如果影响"能不能做"，改 02。**

## 1. 目标用户与 JTBD

JTBD（Jobs To Be Done）= 用户在什么情境下想完成什么，而不只是"他是什么人"。

| 角色 | 核心 Job | 现在的替代方案 | 会换用我们的触发条件 | 会放弃我们的原因 |
|---|---|---|---|---|
| 科研人员 | 「我要读懂这篇 60 页英文论文，图表和公式不能乱，最好能中英对照着看」 | 复制到 DeepL 网页版，按段贴 | 论文超过 20 页、DeepL 免费额度不够、怕未发表数据外泄 | 译后排版错乱，还不如直接看英文 |
| 法务 / 商务 | 「这份 300 页扫描合同要翻成中文给老板看，内容绝对不能外传」 | 外包翻译（贵、慢、有泄密风险） | 合同涉密、时间紧、页数大 | OCR 识别错关键数字/条款编号 |
| 工程人员 | 「900 页英文设备手册，扫的，我要能搜索关键词」 | 拿着 PDF 硬啃英文 | 手册是扫描件、需要 Ctrl+F 检索 | 大文件跑到一半崩了，白跑 |
| 内容/字幕组 | 「一批 SRT 字幕要中文，时间轴不能动」 | 手工逐条改 | 条数上百条 | 时间轴错位，还不如手工 |
| 办公场景 | 「一批 DOCX/PPTX 要双语版发给客户」 | 逐份复制粘贴 | 超过 10 份 | 样式、母版、表格被破坏 |

**共同点（决定产品形态的三条）**：
1. 他们的文件都**不能上传**（隐私是第一诉求，不是便利）。
2. 他们的文件都**不小**（页数是云服务的第一道墙）。
3. 他们都要**结构还在**（不是"能看懂大意"，是"能拿去用"）。

## 2. 关键用户旅程

每条旅程格式：**触发 → 步骤 → 预期耗时 → 失败点 → 成功信号**。

### 旅程 A · 首次使用（决定留存的那 5 分钟）

| 阶段 | 用户动作 | 系统响应 | 设计要点 |
|---|---|---|---|
| A1 | 双击安装包 | Windows SmartScreen 警告"未知发布者" | 安装向导首页直说"本程序不联网"，降低未知恐惧 |
| A2 | 首次启动 | 3 秒内出主窗口，后台并行自检 Ollama | **窗口先出来，自检结果后补**，不阻塞启动 |
| A3 | 看到「未检测到 Ollama」 | 内联卡片：一句原因 + 「去下载 Ollama」按钮 + 「我已装好，重新检测」 | 不说"连接失败"，说"没找到 Ollama 服务" |
| A4 | 装好 Ollama 回来点重新检测 | 列出已装模型；若一个都没有，推荐 `translategemma:12b` 与 `qwen3:8b` 两个选项（标注体积与许可） | 推荐要说明"为什么推荐这个" |
| A5 | 点「下载模型」 | 进度条 + 速度 + 剩余时间；可后台进行并回到任务页 | 8 GB 下载是长任务，**必须可离开当前页** |
| A6 | 拖入一个 PDF | 立即入队一行，显示"待处理"与预估 | 拖入即给反馈，不等解析完 |
| A7 | 点「开始」 | 每页级进度、当前阶段（解析/OCR/翻译/生成）、已用时 | 阶段名要让外行看懂："正在识别扫描页文字" 而不是 "OCR" |
| A8 | 完成 | 行状态变"完成"，右侧出现「打开文件」「打开目录」 | 一键到达产物，不要让用户去找 |

**预期耗时**：装模型 5–15 分钟（取决于网速），之后第一次翻译 20 页约 1 分钟。
**失败点**：A3 卡住（用户不知道 Ollama 是什么）。**对策**：文案里给"这是什么/为什么需要/要多大空间"三句话，不甩链接了事。
**成功信号**：用户在 5 分钟内拿到第一份自己文件的译文。

### 旅程 B · 批量处理

```
拖入 12 个混合格式文件
→ 队列显示 12 行，每行右侧标出识别到的格式与页数
→ 出现一条汇总栏：「12 个文件 · 共 1,847 页 · 预计 2 小时 10 分」
→ 统一设置输出格式（PDF / DOCX / Markdown）
→ 开始 → 逐行推进，失败的单独标红且不阻塞后续
→ 全部结束 → 汇总：「11 成功 · 1 失败」+「查看失败详情」
```

**设计要点**：
- **单文件失败不得中断队列**（对应 FR-6.4）。失败行保留在列表里，可单独重试。
- 输出格式选择要**按文件类型自动给默认值**：PDF→PDF 保排、DOCX→DOCX、SRT→SRT。混合队列里出现"输出 PDF 但输入不是 PDF"时，按行给出降级说明，而不是全局弹警告。
- 队列总耗时估算要允许误差 ±30%，并在进行中动态修正。

### 旅程 C · 断点续翻

```
昨天跑到 40% 关了软件
→ 今天打开 → 任务页顶部一条横幅：「有 1 个任务未完成（324/800 页）· 继续 / 放弃」
→ 点继续 → 从 324 页开始，前 324 页不重翻（TM 命中即跳过）
→ 进度显示「已复用 2,140 段译文，节省约 46 分钟」
```

**设计要点**：复用收益要**显式告诉用户**，否则用户不知道这个功能存在。

### 旅程 D · 术语贯穿（法务/技术场景）

```
任务页 → 术语表页 → 导入 CSV（source,target,case_sensitive,do_not_translate）
→ 导入前后各显示条数，冲突项（同源不同译）单独列出待选择
→ 回到任务 → 译文里强制替换生效
→ 完成 → 报告里显示「术语命中 87 处」
```

**设计要点**：术语表是"专业用户才用"的功能，入口不能太抢眼，但命中结果必须可见——否则用户无法判断术语到底生效没有。

### 旅程 E · 失败恢复（这条旅程决定口碑）

| 失败类型 | 用户看到 | 可做的动作 | 不能只说 |
|---|---|---|---|
| Ollama 没启动 | 顶部黄条「Ollama 未运行，翻译无法进行」 | 「启动指引」「重试」 | 「连接被拒绝」 |
| 模型不存在 | 行内红字「模型 translategemma:12b 未安装」 | 「立即下载」「换模型」 | 「404」 |
| 扫描件 OCR 失败 | 行内黄字「第 12 页无法识别文字（图像质量过低）」+ 该页保留原图 | 「跳过该页继续」「查看该页」 | 整份任务失败 |
| 磁盘空间不足 | 开始前预检查：「输出需要约 2.3 GB，D 盘剩余 1.1 GB」 | 「换目录」 | 跑到一半 OSError |
| 输出目录不可写 | 开始前预检查 | 「换目录」「以管理员身份」 | 完成后才报错 |
| 文档加密 | 「该 PDF 有打开密码，暂不支持」 | 「换文件」 | 一直转圈 |

**硬规则**：**能在开始前发现的错误，绝不放到跑到一半才报**。预检查清单见 §5.2。

## 3. 信息架构

```
LinguaForge 主窗口
├── 侧边导航（4 项，常驻）
│   ├── ① 任务        ← 默认页，90% 的时间都在这里
│   ├── ② 模型        ← 低频，但首次启动必经
│   ├── ③ 术语表      ← 专业用户
│   └── ④ 设置        ← 极低频
├── 全局元素（不随页面切换）
│   ├── 顶部健康条：Ollama ● / 模型 ● / OCR ● / 磁盘 ●（四项状态点）
│   ├── 右下角任务托盘：后台任务数 + 总进度（点击跳回任务页）
│   └── 底栏：版本号 · 日志入口 · 语言切换
└── 模态层
    ├── 并排预览（原文 / 译文，可拖分隔条）
    ├── 模型下载进度（可最小化）
    └── 确认类对话框（删除任务、清空队列）
```

**导航原则**：四个页面之间**不互相跳转**，跨页动作通过顶部健康条与托盘完成。避免"从设置页跳到模型页再跳回来"的迷路。

## 4. 逐屏交互规格

### 4.1 任务页（TaskPage）

| 区域 | 控件 | 行为 | 空态 | 不可用态 |
|---|---|---|---|---|
| 顶部 | 拖放区（占屏 30%） | 支持拖入文件与文件夹；拖入时整区高亮描边 | 居中插画 + 「把文件拖到这里」+ 「选择文件」按钮 | 翻译进行中仍可拖入，新文件追加到队尾 |
| 工具条 | 输出格式下拉 | **7 项**：Markdown / TXT / PDF（原位回填）/ DOCX / PPTX / XLSX / SRT（`ui/worker.py::OUTPUT_FORMATS` 实际取值） | — | 无文件时禁用 |
| 工具条 | 双语对照开关 | 独立复选框，映射 `OutputConfig.bilingual`，与输出格式正交（当前仅 CLI `--bilingual` 可达，UI 待 P4-2 补） | 默认关 | — |
| 工具条 | 输出目录 | 留空 = 与源文件同目录；右侧「选择…」 | 显示灰字"与源文件同目录" | — |
| 工具条 | 开始 / 暂停 / 取消 | 三态互斥：无任务→禁用；进行中→暂停+取消；暂停中→继续+取消 | — | — |
| 队列表 | 列：文件名 / 格式 / 页数 / 状态 / 进度 / 耗时 / 操作 | 双击行 → 打开并排预览 | 表格隐藏，只显示拖放区 | — |
| 队列表 | 行状态徽标 | 待处理（灰）/ 解析中（蓝）/ 翻译中（蓝，带百分比）/ 完成（绿）/ 部分完成（黄，标明 N 页失败）/ 失败（红） | — | — |
| 队列表 | 右键菜单 | 移除 / 重试 / 打开输出 / 打开源文件 / 复制错误信息 | — | 完成项才有"打开输出" |

**关键交互**：
- 拖入重复文件（同路径同大小）时提示「已在队列中，跳过」而不是重复入队。
- 队列行可排序但**执行顺序恒按入队顺序**（避免用户以为拖动能改执行顺序）。
- 单行失败后，该行保留且「重试」可用；「开始」按钮变成「重试失败项」。

### 4.2 模型页（ModelPage）

| 区域 | 控件 | 行为 |
|---|---|---|
| 状态卡 | Ollama 连接状态 | ●已连接（含版本号）/ ●未运行（含启动指引）/ ●未安装（含下载链接） |
| 模型列表 | 已装模型表 | 列：模型名 / 参数规模 / 体积 / 上下文长度 / 许可标签 / 当前使用 |
| 模型列表 | 「设为默认」 | 单选，写回 `config.ollama.model` |
| 推荐区 | 推荐模型卡片 ×2–3 | 每个卡片：名称、体积、适合的内存档、许可提示、下载按钮 |
| 下载区 | 进度条 | 状态文本（拉取清单/下载层/校验）+ 百分比 + 速度 + 剩余时间；可最小化 |

**设计要点**：
- 许可标签必须显示。`translategemma:*` 标「商用前请确认 Gemma 条款」，`qwen3:*` 标「Apache-2.0，可商用」。
- 推荐卡片要按本机内存给默认推荐，并写明依据：「检测到 31.8 GB 内存，推荐 12B」。

### 4.3 术语表页（GlossaryPage）

| 区域 | 控件 | 行为 |
|---|---|---|
| 工具条 | 导入 CSV / 导出 CSV / 新增 / 删除选中 | 导入时校验四列；冲突项弹窗逐条确认 |
| 表格 | 列：原文 / 译文 / 区分大小写 / 不翻译 / 备注 | 单元格可直接编辑，失焦保存 |
| 搜索框 | 按原文或译文过滤 | 实时过滤，显示「匹配 N / 共 M 条」 |

**关键交互**：术语表为空时显示「还没有术语表 · 导入 CSV 或用模板开始」，并提供「下载模板」。

### 4.4 设置页（SettingsPage）

分组：翻译（源语言/目标语言/温度/批次大小/超时/重试）、OCR（开关/引擎/DPI/置信度阈值/语言）、性能（窗口页数/内存软阈值/并发）、输出（命名规则/双语开关）、界面（语言/主题）。

**设计要点**：每个高级参数旁边有 ⓘ，悬浮显示「默认值 + 什么时候需要改」。**默认展开基础项，高级项折叠**——90% 的用户不该看到 `num_ctx`。

### 4.5 并排预览（PreviewDialog）

- 左原文右译文，中间可拖动分隔条（默认 50:50）。
- 顶部：页码输入框 + 上一页/下一页 + 缩放（适应宽度/100%/200%）。
- 译文侧高亮失败块（红底细边），点一下显示"此段翻译失败，原因：…"。
- 底部：跟随滚动的复选框（默认开）。

## 5. 状态矩阵

### 5.1 全局环境态

| 状态 | 检测时机 | 用户看到 | 允许的操作 | 系统行为 |
|---|---|---|---|---|
| Ollama 未安装 | 启动时 | 顶部黄条 + 任务页禁用「开始」 | 打开下载页 | 不反复重试探测 |
| Ollama 未运行 | 启动时 + 每次开始前 | 顶部黄条 + 「重新检测」 | 重新检测 | 探测超时 2 s |
| 无可用模型 | 启动时 + 模型页 | 黄条「已装 0 个模型」 | 跳模型页 | — |
| 模型加载中 | 首次请求 | 行内「模型加载中，首次约 30 秒」 | 等待 | 不判失败 |
| 磁盘不足 | 开始任务前 | 模态：「需要约 N GB，可用 M GB」 | 换目录 / 取消 | 阻塞该任务 |
| 输出目录不可写 | 开始任务前 | 模态：「目录不可写」 | 换目录 | 阻塞 |
| OCR 模型缺失 | 首次遇到扫描页 | 行内黄字「OCR 组件缺失，扫描页将被跳过」 | 继续（跳过）/ 取消 | 仅跳过扫描页 |

### 5.2 开始前预检查清单（工程必做）

1. Ollama 可达（`/api/version`，2 s 超时）
2. 目标模型存在于 `/api/tags`
3. 输出目录存在且可写（尝试创建临时文件再删除）
4. 磁盘剩余 ≥ 预估输出的 1.5 倍
5. 输入文件可读、未加密、非 0 字节
6. 输入格式在 `SUPPORTED_IN` 内

任一项失败 → 在**开始前**给出可操作提示，不进入执行。

### 5.3 单任务态

`待处理 → 解析中 → （需要时）OCR 中 → 翻译中 → 生成中 → 完成 / 部分完成 / 失败 / 已取消`

- **部分完成**：至少 1 块翻译失败但流程跑完。必须给「哪些页、为什么」。
- **失败**：解析阶段就失败（打不开/加密/格式不支持），无产物。
- **取消**：保留已译内容，可续跑。

## 6. 文案规范

### 6.1 错误文案三段式（强制）

```
【发生了什么】+【为什么会这样】+【你可以怎么做】
```

| ✗ 不合格 | ✓ 合格 |
|---|---|
| `ConnectionRefusedError: [WinError 10061]` | 没连上 Ollama 服务（本机翻译引擎）。它可能没有启动。请先打开 Ollama，再点「重新检测」。 |
| `OCRError: OCR 失败` | 第 12 页的文字识别失败。这一页可能是纯图片或扫描质量过低。可以跳过这一页继续，或换一份更清晰的扫描件。 |
| `PermissionError: [Errno 13]` | 无法写入输出目录。这个目录可能只读或被其他程序占用。请换一个目录（例如「文档」下新建文件夹）。 |

### 6.2 用词表

| 用我们的话 | 不要用 | 原因 |
|---|---|---|
| Ollama / 本机翻译引擎 | LLM、大模型服务 | 外行不知道 LLM 是什么；两个说法并列出现一次即可建立映射 |
| 扫描件 / 扫描页 | 无文本层页面 | 用户不关心 PDF 内部结构 |
| 文字识别 | OCR | 首次出现可以「文字识别（OCR）」 |
| 保排翻译 | 原位回填 | 回填是实现词，不是用户词 |
| 术语表 | 翻译记忆 / TM | TM 是内部机制，用户只理解术语表 |
| 断点续翻 | 增量翻译 | — |

### 6.3 长度与语气

- 内联提示 ≤ 40 字；对话框说明 ≤ 120 字；帮助文档不限。
- 语气：陈述事实，不用感叹号，不卖萌，不责备用户（禁用"您操作有误"）。
- 中文标点用全角；中英混排时英文两侧留一个空格（如「支持 PDF 与 DOCX」）。

## 7. 反馈层级

| 层级 | 用于 | 存活时间 | 是否可关闭 |
|---|---|---|---|
| 行内状态 | 单文件/单页的进展与轻错误 | 随状态变化 | 随状态消失 |
| 顶部健康条 | 全局环境问题（Ollama/模型/磁盘） | 直到恢复 | 不可关闭，可折叠到图标 |
| Toast（右下） | 操作成功的确认（已复制、已导出） | 4 s | 可手动关 |
| 模态对话框 | 需要决策的阻塞问题（磁盘不足、术语冲突） | 直到用户选择 | 必须选择 |
| 仅日志 | 内部异常细节、堆栈 | 持久 | — |

**规则**：同一个错误**只在一个层级出现**。不要既弹模态又在行里标红又在日志里喊——这会让用户以为有三个问题。

## 8. 首次运行引导

四步，每步都可跳过（跳过不阻塞使用，只在顶部留提醒）：

1. **检测环境**（自动，3 秒）→ 结果三选一：就绪 / 缺 Ollama / 缺模型
2. **装 Ollama**（若缺）→ 三句话说明 + 官网按钮 + 「我已装好」复活检测
3. **选模型**（若缺）→ 两个推荐卡片（12B / 8B），显示体积与所需内存
4. **试翻一份样例**（可选）→ 内置一份 2 页英文样例，30 秒跑完，让用户看到完整闭环

**不要做的**：注册账号、填问卷、选主题、看功能介绍轮播。离线工具用户对仪式感零耐心。
