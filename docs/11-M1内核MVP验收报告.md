│   └── render.py       pypdfium2 页面位图渲染（OCR / 预览共用）
├── translate/
│   ├── ollama_client.py  httpx 薄封装
│   └── translator.py     编号化 JSON 契约 + 5 级降级链 + 术语表 + TM
├── writers/
│   ├── markdown.py     块类型 -> Markdown；支持按窗口增量渲染
│   └── text.py         纯文本
├── ocr.py              RapidOCR(ONNX) 封装，毫秒级加载、置信度过滤

**关键约束落实**：`pipeline.py` 及以上模块**不 import 任何 Qt 符号**，可无头运行、可单测 —— 为 M5 的 UI 层留出干净的接缝。

## 3. 三个必须记下来的实现坑

### 3.1 `pdfplumber.extract_words()` 默认不返回字号与字体

`page.extract_words()` 的词属性里 `size` 和 `fontname` **都是 `None`**（这两个属性不在默认聚合列表里），只有传入 `extra_attrs=["size","fontname"]` 才有值。直接用它会让字号推断整体退化为常量，标题识别、层级推断、页眉页脚判断全部失效 —— 表现为「所有块都是 10pt 正文」。

**对策**：不用 `extract_words()`，改为 `chars_to_words(page.chars)` 自己聚类。`page.chars` 的 `size/fontname/top/x0/x1/bottom` 齐全可靠，且聚类规则（行容差、切词间距）完全可控。

### 3.2 段落合并的「短行」判定不能用绝对像素

判断「上一行是段末」的正统信号是**短行**（没写满版心）。但如果用 `max(x1)` 作版心右边线，会被大字号标题（往往比正文更宽）抬高，导致**正文满行也被判为短行**，结果每个句号都断成一段。

**对策**：版心基准只用**正文字号的行**计算（`abs(size - body_size) <= 1.2`），并且短行判定改为**比例**而非像素：`(行右边界 - 版心左边界) < 版心宽 × 0.85`。

### 3.3 页码每页都不同，指纹法抓不到

页眉页脚用「跨页重复文本」做指纹能抓到 `XJ-2000 Manual — Confidential`，但 `Page 1 / Page 2 / …` 每页都不一样，永远不重复。

**对策**：双策略 —— 指纹（重复文本）+ 位置（页底 6.5% 内、页顶 5.5% 内、长度与字号受限）+ 页码正则（`Page 3`、`3 / 12`、`第 3 页`、`- 3 -`）。

## 5. 降级链设计

模型输出不可靠是常态，所以「解析失败」必须能自愈。5 级链条：

| 级别 | 触发条件 | 动作 |
|---|---|---|
| L1 | 默认 | `format=json` 整批请求 |
| L2 | L1 解析不对齐 | 去掉 `format:json` 重发（部分模型受限解码时会输出空/重复） |
| L3 | L2 仍不对齐 | 批次减半再试（长上下文易漏项） |
| L4 | 以上都失败 | 换 `fallback_models`（4b / qwen3:8b） |
| L5 | 全部失败 | 逐条翻译，慢但必中 |

解析器本身也有 4 层兜底：整体 `json.loads` → 截取首 `{` 到末 `}` → 正则抽 `id/text` 对 → 编号行 `1. 译文`。实测 `translategemma:12b` 在不加 `format=json` 时会把结果包在 ` ```json ` 里，第二层可剥掉。

## 6. 已知限制（不阻塞 M1 出口）

1. **双栏排版**：目前按「列中点」粗分左右栏再按 y 排序，学术论文的跨栏标题/图注可能顺序错乱。
2. **跨页段落**：段落在页边界被切开，跨页续段不合并（M2 与排版回填一起处理）。
3. **表格无表头识别**：`tables` 直接取第一个非空行作表头。
4. **无图片提取**：图片块跳过（DocIR 有 `assets` 字段预留）。
5. **OCR 表格**：扫描件表格按普通文本行处理，不重建表格结构。
6. **PDF 只读不写**：M1 输出 Markdown/TXT；保排 PDF 回填在 M2。
