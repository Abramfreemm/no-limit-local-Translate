## 0. 核心结论（先给判断，再给依据）

**不建议从零重写。建议做"增量重构 + 补齐门禁"，共 18 人日：0.1.0（P0–P4，10 人日）+ 0.2.0（P5–P8，8 人日）。**

> 原判断为 16 人日（单版本）。定稿时为「失败恢复」单列 P4（+2 人日，D11），并把批次切到两个版本（D10）。

三条理由：

1. **代码质量整体合格**，分层清晰、无 TODO 腐烂、核心逻辑有测试。重写=把已经踩完的坑重踩一遍（PDF 剥离回填、字体 ToUnicode、双语序列化隔离，这三点任何一个重来都要再花一周）。
2. **真正的缺陷不在架构，在工程纪律**。最大的问题是 CI 里没有任何测试与静态检查——这不是"写得不好"，是"没有防线"。
3. **重写成本 4–6 周且无法并行验证**；增量重构每一步都可独立发版、可回退。

**唯一值得"重写"的是 UI 层的样式实现**（11 个文件里的字面量样式），以及**异常体系**（9 个类合并为 1 + 错误码）。这两块范围可控，其余全部保留。

## 4. 六条硬发现（每条都有代码证据）

### 4-1 · CI 里没有任何测试与静态检查

```
$ grep -n "ruff\|pytest\|mypy\|pip-audit" .github/workflows/*.yml
（无结果）
```

`release.yml` 只做了：安装依赖 → 准备资源 → PyInstaller → 冒烟（`--version`）→ iscc → 上传。

**后果**：26 个单测、`ruff` 配置、`12` 号文档设计的 L0/L1 门禁，**全部只在本地手动跑过**。任何人 push 破坏测试，CI 会显示绿色。

**这是当前最高优先级的缺陷。** 一条守不住的测试等于没有测试。

### 4-2 · ruff 306 个错误从未清理

```
UP006 non-pep585-annotation      155   （List[str] → list[str]）
UP045 non-pep604-annotation       51   （Optional[X] → X | None）
UP035 deprecated-import           38   （typing.List 等）
UP037 quoted-annotation           27
E741  ambiguous-variable-name     15   （变量名 l/I/O）
F401  unused-import                6
F841  unused-variable              1
```

前四类（271 个）是纯风格，`ruff --fix` 可一次清完。但 **F401/F841/E741 是真实缺陷信号**：未使用的导入、未使用的变量、歧义命名，通常意味着"写完没跑"或"改了没清"。

### 4-3 · 零日志落盘

`requirements.txt` 有 `loguru>=0.7`，但全代码库**没有任何 `logger.add(...)` 调用**。GUI 模式（`console=False`）下 `sys.stderr` 不可见，未捕获异常的 traceback 直接消失。

**后果**：用户报"闪退"或"跑了很久没结果"，我们手上零信息（19 号整份文档的 Runbook 因此无法执行）。

### 4-4 · 固定临时目录，不清理

```python
# linguaforge/writers/pdf_rebuild.py:255
self.tmp_dir = Path(tmp_dir) if tmp_dir else Path(tempfile.gettempdir()) / "lf_parts"
```

问题：多实例冲突（互相覆盖分片）、进程被杀后**译文分片永久残留**、`%TEMP%` 下路径可预测。

### 4-5 · 内存护栏只有配置，没有实现

`PerfConfig.memory_warn_mb = 1500` 被定义、被读取为配置项，但**没有任何代码根据 RSS 执行降档或中止**。`psutil` 在依赖里，同样未使用。

**后果**：`02` §NFR 的"内存护栏"与 `06` M6 的交付项，实际是**空实现**。

### 4-6 · 二进制输出格式是内存黑洞

```python
# linguaforge/pipeline.py
_BINARY_FMTS = {"docx", "pptx", "xlsx", "srt", "vtt"}
# 注释原文：需要"收集完整文档再一次性落盘"
```

解析侧已实测极优（1000 页 RSS 增量 9.6 MB，见 18 号 §4.1），但**这两种格式走的是完全不同的路径**：全部块对象驻留内存直到最后一次性写出。这是 `_BINARY_FMTS` 的已知设计取舍，但**从未测过 1000 页场景的峰值**。

## 6. v2 目标架构（与 v1 的差异）

**架构骨架不变**（分层、DocIR、流式、适配器契约都保留）。变的是四处横切能力：

```
v1                                    v2
────────────────────────────────────────────────────────────
异常：9 个类 → UI 显示 str(e)          异常：Problem(code,severity,params) → 模板渲染
日志：无                               日志：落盘 + 脱敏 + 诊断包
门禁：CI 只打包                        门禁：lint/type/test/license/audit/体积
UI：样式字面量                          UI：token → QSS 单一来源
护栏：配置项（空实现）                  护栏：RSS 采样 → 降档/暂停/中止
```

**新增横切模块**（都是薄层，不改业务逻辑）：

```
linguaforge/
├── core/
│   ├── problems.py      ← 新增：Problem / Severity / 错误码常量
│   ├── logging.py       ← 新增：日志初始化、脱敏、轮转
│   ├── guards.py        ← 新增：解析超时、尺寸上限、zip 炸弹、文件名净化
│   └── memory.py        ← 新增：RSS 采样与降档回调
└── ui/theme/
    ├── tokens.py        ← 新增：全部设计 token
    └── qss.py           ← 新增：由 token 生成 QSS
```

### P0 · 建立门禁 + 依赖锁定（1.5 人日）· 0.1.0 ★ 必须先做

**做什么**
1. 新增 `.github/workflows/ci.yml`：`ruff check` + `ruff format --check` + `pytest -q` + `pip-licenses --fail-on` + `pip-audit`
2. 先 `ruff check --fix` 清 253 个可自动修的；剩余 53 个手工处理或在 `pyproject.toml` 里显式忽略并写理由

4. 生成 `requirements.lock`（`pip freeze` 精度）并让 CI 按锁文件安装（D14）

**验收**：故意提交一个失败测试 → CI 变红 → 发版被阻断；`pip-audit -r requirements.lock` 0 高危。

**为什么排第一**：后面 8 张卡全靠它兜底。没有这一步，后面每一步都在裸奔。

### P4 · 失败恢复与预检查（2 人日）· 0.1.0 ★ 决定留存的一批

**为什么插在安全之后、内存之前**：前三批解决的是"别出事"，这一批解决的是"出了事用户还愿意继续用"。当前 `PipelineResult.errors` 里全是中文字符串拼接（`f"打开失败: {e}"`），UI 直接把异常类名抛给用户；而磁盘不足、目录不可写、PDF 加密这三类错误，本来在开工前 0.3 秒就能查出来，现在要跑到一半才炸。

**做什么**
1. `core/preflight.py`：7 条开工前检查（Ollama 可达 / 模型存在 / 目录可写 / 磁盘余量 ≥ 预估 1.2 倍 / PDF 未加密 / 文件可读非空 / >500 页提示预估耗时），总耗时 < 1.5 s
2. `ui/main_window.py`：顶部健康条（Ollama ● / 模型 ● / OCR ● / 磁盘 ●）
3. `ui/task_page.py` + `ui/i18n.py`：旅程 E 六类失败的三段式文案（发生了什么 → 为什么 → 我能做什么），每类至少一个可点动作
4. `ui/worker.py`：开始任务前调用 preflight，结果回传 UI 而不是抛异常

**验收**：
- 停掉 Ollama 后开始任务 → UI 显示「没连上 Ollama」+ 启动指引，退出码非 0 且错误码为 `LF-PRE-4001`
- 输出目录设为只读 → 开工前即被拦，不进解析阶段
- 六类失败各自有单测（monkeypatch 制造条件），预检查总耗时 < 1.5 s

### P5 · 内存护栏 + 二进制输出（2.5 人日）· 0.2.0

**做什么**

**验收**：1000 页 DOCX 输出峰值 RSS ≤ 800 MB（当前未测：先测基线，再定阈值，不得先写阈值后凑数据）。
