## 0. 现状与问题

| 事实 | 后果 |
|---|---|
| 异常体系是 9 个各自独立的 `RuntimeError` 子类（`OCRError`、`DocxParseError`、`HtmlParseError`、`ImageParseError`、`PptxParseError`、`SrtParseError`、`XlsxParseError`、`OllamaError`、`OllamaUnavailable`） | 无法按类别统计、无法国际化、无法让用户搜索到对应帮助 |
| UI 直接把 `str(e)` 显示给用户（如 `Ollama 返回 500: {"error":"..."}`） | 用户看不懂，也不知道下一步做什么 |
| **`loguru` 在依赖里但从未启用，没有任何日志落盘** | 用户报问题时，我们手上零信息。只能让他"再试一次" |
| GUI 模式 `console=False`，未捕获异常的 traceback 打到不可见的 stderr | 表现为"闪退"，无任何线索 |
| `PipelineResult.errors` 是 `list[str]` 自由文本（如 `p3 OCR 失败: ...`） | 无法结构化聚合，无法做失败率统计 |

**这份文档要把"出错"从"用户体验事故"变成"可分类、可定位、可统计的工程对象"。**

## 1. 错误码体系设计

### 1.1 编码规则

```
LF-<域><两位序号>          例：LF-E04
```

| 域 | 含义 | 典型场景 |
|---|---|---|
| **E** | Environment 环境与依赖 | Ollama、模型、OCR 组件、磁盘 |
| **D** | Document 文档输入 | 格式、损坏、加密、结构异常 |
| **T** | Translation 翻译过程 | 模型输出、超时、降级耗尽 |
| **O** | Output 输出与文件系统 | 写出、字体、路径 |
| **S** | System 内部 | 未捕获异常、数据库、内存 |
| **U** | Usage 用户操作 | 队列为空、未选模型 |

**规则**：
- 码一旦分配**永不复用**（即使该场景删除），避免历史日志歧义。
- 新增码只能追加，不能改变既有码的语义。
- 每个码必须能回答四个问题：**谁的错、能不能继续、用户能做什么、日志里记什么。**

### 1.2 严重级（Severity）

| 级 | 含义 | UI 表现 | 是否中止任务 |
|---|---|---|---|
| **B** Blocker | 无法开始 | 模态或顶部红条 | 是（开始前） |
| **F** Failure | 当前任务失败 | 行内红字 | 是（当前文件） |
| **D** Degraded | 降级继续，结果有损 | 行内黄字 / 报告 | 否 |
| **W** Warning | 可继续，但需注意 | 顶部黄条 | 否 |
| **I** Info | 仅记录 | 无 | 否 |

## 3. 异常类 → 错误码映射（改造依据）

| 现有异常 | 映射到 | 改造动作 |
|---|---|---|
| `OllamaUnavailable` | `LF-E01` / `LF-E02` | 需区分"未启动"与"未安装"（当前合并） |
| `OllamaError` | `LF-T03` / `LF-E05` / `LF-T06` | 需按 HTTP 状态码细分（400/404/500/timeout） |
| `OCRError` | `LF-E07` / `LF-E08` / `LF-T08` | 需区分组件缺失与单页识别失败 |
| `DocxParseError` `PptxParseError` `XlsxParseError` `HtmlParseError` `SrtParseError` `ImageParseError` | `LF-D05` + 格式标签 | **合并为一个 `DocumentParseError(format=...)`**，避免 6 个类各自演化 |
| `IndexError`（页码越界） | 不应到用户层（内部断言） | 改为内部 `assert` 或 `LF-S01` |
| `FileNotFoundError` | `LF-D01` | 统一在 pipeline 入口转换 |
| `PipelineResult.errors: list[str]` | `list[Problem]`（含 code/severity/params） | **数据结构改造**，见 §4 |

**目标结构**：

```python
@dataclass(frozen=True)
class Problem:
    code: str                 # "LF-E04"
    severity: Severity        # B/F/D/W/I
    params: dict[str, Any]    # 文案模板变量
    detail: str = ""          # 仅进日志，不给用户看
    page: int | None = None
    block_ids: list[str] = field(default_factory=list)
```

UI 层只做一件事：`tr(problem.code, **problem.params)` → 取本地化文案。**UI 不再拼接任何错误字符串。**

## 4. 日志规范

### 4.1 落盘位置与轮转

| 平台 | 路径 |
|---|---|
| Windows | `%LOCALAPPDATA%\LinguaForge\logs\linguaforge.log` |
| macOS | `~/Library/Logs/LinguaForge/linguaforge.log` |

- 轮转：单文件 5 MB，保留 3 个（`linguaforge.log` / `.1` / `.2`），总量上限 15 MB。
- 级别：默认 `INFO`；设置页可开 `DEBUG`（会提示"日志量增大"）。
- **首行必须写**：版本号、OS 版本、Python 版本、Ollama 版本、模型名、启动时间。

### 4.2 记录什么 / 不记什么（隐私红线）

| 记 | 不记 |
|---|---|
| 页码、块数、耗时、字节数 | **文档正文**（`block.text` / `translated`） |
| 异常类型与错误码 | 完整文件路径（改为 `文件名 + hash 前 8 位`） |
| 模型名、参数（temperature 等） | 用户目录路径中的用户名 |
| HTTP 状态码、耗时 | 完整响应体（截断至 200 字符且仅在 DEBUG） |
| 内存/磁盘采样 | 术语表内容 |

**理由**：日志会被用户复制粘贴发到公开 issue。日志里出现合同正文是不可接受的。

### 4.3 关键事件清单（必须打点）

| 事件 | 级别 | 字段 |
|---|---|---|
| 应用启动 | INFO | version, os, py, olla_version, model |
| 环境自检结果 | INFO | ollama, model, ocr, disk 四项状态 |
| 任务开始 | INFO | task_id, pages, fmt, src_lang, dst_lang, model |
| 每页完成 | DEBUG | page, blocks, ms, ocr_used |
| 每批翻译完成 | DEBUG | batch_size, ms, retries, tm_hits |
| 降级链触发 | WARNING | level(L1–L5), reason |
| 任务结束 | INFO | ok, pages_done, blocks_failed, elapsed, output |
| 任何 Problem | 按 severity | code, severity, params, page |
| 未捕获异常 | ERROR | traceback |

## 5. 崩溃与诊断包

### 5.1 全局异常兜底（当前缺失）

```python
# app/main.py
def _excepthook(exc_type, exc, tb):
    log.error("unhandled", exc_info=(exc_type, exc, tb))
    show_crash_dialog(Problem("LF-S01", Severity.F,
                              {"version": __version__}, detail=str(exc)))

sys.excepthook = _excepthook
# PySide6 还需接管 Qt 事件循环内的异常（否则窗口未响应但进程仍活）
```

**注意**：PyInstaller `console=False` 时 stderr 不可写，`sys.stderr` 为 `None`，直接用 `print` 会二次崩溃。必须显式兜底。

### 5.2 诊断包（"复制诊断信息"按钮）

用户点一下，生成一段可直接粘贴到 issue 的文本：

```
LinguaForge 0.1.0
Windows 11 23H2 (22631.4169) · Python 3.13.14 · 16 核 / 31.8 GB
Ollama 0.32.15 (127.0.0.1:11434) · 模型 translategemma:12b (8.1 GB)
OCR rapidocr 1.2.3 (CPU) · 磁盘 D: 剩余 812 GB
最近错误：
  LF-D05  FILE_2f8a1c.pdf  p12  解析异常(KeyError)  2m 前
  LF-T06  FILE_2f8a1c.pdf  p12  翻译失败 3 段        2m 前
日志：[打开日志目录]
```

**不含**：文件名（只留 hash 前 8 位 + 扩展名）、路径、任何正文。

## 6. 故障排查手册（Runbook）

按"用户报的症状"索引，不按代码模块索引 —— 排障的人先看到的是症状。

### R1 · 双击没反应 / 闪退

| 步骤 | 动作 | 判断 |
|---|---|---|
| 1 | 看 `%LOCALAPPDATA%\LinguaForge\logs\` 是否有日志 | 无目录 = 启动前就挂了（缺 DLL / 杀软拦截） |
| 2 | 命令行跑 `LinguaForge.exe` 看 stderr | 有 traceback → 按 S01 处理 |
| 3 | 检查杀软隔离区 | PyInstaller 产物常被误报 |
| 4 | 用 `linguaforge-cli.exe --version` 验证核心能否跑 | CLI 能跑 = GUI 层问题（Qt 插件缺失） |

### R2 · 界面出来了但一直"未检测到 Ollama"

| 步骤 | 动作 | 判断 |
|---|---|---|
| 1 | 浏览器访问 `http://127.0.0.1:11434/api/version` | 有 JSON = 客户端问题；无响应 = 服务没起 |
| 2 | 终端 `ollama serve` 看是否报端口占用 | 端口占用 = 另一个实例在跑 |
| 3 | 检查 `HTTP_PROXY` / `HTTPS_PROXY` | 代理会劫持回环（本机实测过：被代理成 502） |
| 4 | 检查 `OLLAMA_HOST` | 非 127.0.0.1 则需改回 |

### R3 · 翻译到一半卡住不动

| 步骤 | 动作 | 判断 |
|---|---|---|
| 1 | 看日志最后一条 `每批翻译完成` | 时间戳停住 = 模型侧慢（首次加载 12B 约 30 s） |
| 2 | `ollama ps` 看模型是否在跑 | 不在 = 模型被换出（内存不足） |
| 3 | 看 RSS 是否接近阈值 | 接近 = 降档未生效（见 18 号 §6） |
| 4 | 等待超时（300 s）后应出 `LF-T03` | 无此错误码 = 超时机制失效 |

### R4 · 输出 PDF 中文变方框

| 步骤 | 动作 |
|---|---|
| 1 | 确认 `_internal/resources/fonts/NotoSansSC-Regular.ttf` 存在 |
| 2 | 查日志 `LF-O02`（字体嵌入失败） |
| 3 | 用 pdfplumber 抽取产物文本，若抽取不到但能看见 → ToUnicode 丢失（可变字体子集化问题，M2 已踩过） |

### R5 · 大文件跑到一半内存爆

| 步骤 | 动作 |
|---|---|
| 1 | 确认输出格式是否为 docx/pptx/xlsx（`_BINARY_FMTS` 全量驻留，见 18 号 §4.2） |
| 2 | 改输出为 Markdown 复测，若正常 → 确认是二进制 writer 问题 |
| 3 | 查日志 RSS 曲线，确认降档是否触发 |

### R6 · 断点续翻没生效（重头开始）

| 步骤 | 动作 |
|---|---|

## 7. 反馈闭环（无遥测下的替代方案）

产品不做任何自动上报（隐私承诺）。那怎么知道哪里出错？

| 手段 | 做法 | 能回答什么 |
|---|---|---|
| 诊断包一键复制 | §5.2 | 单个问题的根因 |
| 任务结束报告 | 完成后显示「N 成功 / M 失败 / 失败原因分布」 | 本机质量趋势 |
| 用户可选导出报告 | 导出 JSON（含错误码统计，无正文） | 用户主动反馈时的批量数据 |
| GitHub Issue 模板 | 强制要求贴诊断包 | 降低沟通成本 |

**Issue 模板结构**（`.github/ISSUE_TEMPLATE/bug.yml`）：
```yaml
- 你在做什么（拖入什么格式、多少页、什么输出）
- 期望什么
- 实际发生了什么
- 诊断信息（粘贴）
- 是否可复现（每次 / 偶发）
```
