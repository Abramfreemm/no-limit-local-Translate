# 08 · 测试方案与验收标准

版本 v1.0

## 1. 测试策略

```
         ┌─────────────┐
         │  人工排版评审 │  ← PDF 质量只能靠人眼（建立评分表）
         └─────────────┘
         ┌─────────────┐
         │  端到端 E2E  │  ← 真实文件跑完整流水线
         └─────────────┘
    ┌──────────────────────┐
    │  集成测试（Ollama/OCR）│  ← 可标记 @slow，本地手动跑
    └──────────────────────┘
 ┌────────────────────────────┐
 │  单元测试（Chunker/JSON/SQL） │  ← CI 每次必跑，不依赖 Ollama
 └────────────────────────────┘
```

**原则**：单元测试**绝不依赖 Ollama 与 OCR**（用 Fake 实现），保证 CI 可在无模型环境下运行。

## 3. 单元测试范围（必过）

| 模块 | 用例要点 |
|---|---|
| `chunker` | 不超过 token 预算；不切断段落；超长单段强制切分；空输入 |
| `ollama_client` | 用 Fake HTTP：正常 JSON、条数不符、JSON 损坏、超时；验证降级链逐级触发 |
| `prompt` | 术语注入；特殊字符转义；超长上下文截断 |
| `layout` | 列检测（单/双栏）、页眉页脚剔除、阅读顺序排序 |
| `ir` | 序列化往返一致；bbox 归一化；坐标换算（pt ↔ px ↔ 缩放） |
| `store` | 断点恢复：模拟中断后状态正确；TM 命中；术语替换 |
| `writers/md` | 标题层级、列表、代码块、表格 |
| `paths` | 中文路径、空格路径、超长路径（Windows 260 字符） |

- 真实 OCR 一页扫描图，校验输出结构
- 端到端：F01 → 中文 Markdown
- 端到端：F04 → 可搜索 PDF

## 5. 性能基准（perf/）

| 基准 | 目标 | 方法 |
|---|---|---|
| OCR 单页（CPU, 200 DPI, RapidOCR） | ≤ 2 s | F05 抽样计时 |
| 1000 页流式解析 | 内存峰值 ≤ 1.5 GB，无 OOM | F12 + RSS 采样 |
| SQLite 写入吞吐 | ≥ 5000 块/秒（批量事务） | 批量插入计时 |
| 冷启动到主窗口 | ≤ 5 s | 计时 |
| 翻译吞吐 | 记录基线（页/分钟），UI 用于估算 ETA | 按模型各测一次 |

**RSS 采样工具**：`psutil` 定时采样并输出峰值，纳入 CI 可选项。

## 6. 排版质量人工评分表（M2/M8 使用）

每份样本由评审人按 5 分制打分，3 分及以上视为"可用"。

| 维度 | 5 分 | 3 分 | 1 分 |
|---|---|---|---|
| 文本位置 | 与原文框完全对齐 | 轻微偏移但不影响阅读 | 大面积错位/重叠 |
| 字号适配 | 自然 | 略大/略小 | 溢出框外或不可读 |
| 图片/表格/公式 | 完整保留 | 部分保留 | 丢失或破坏 |
| 栏目与顺序 | 阅读顺序正确 | 偶有跳错 | 顺序混乱 |
| 术语一致性 | 全文一致 | 个别不一致 | 同一术语多种译法 |
| 目录/链接 | 保留 | 部分丢失 | 全丢 |

**通过标准**：F01/F02/F03 三项均分 ≥ 3.5/5（完整版）；精简版首轮 ≥ 3.0/5 并记录整改项。

## 7. 验收清单（发布前逐条勾）

- [ ] A1 断网全流程可用，无外发请求
- [ ] A2a 1000 页跑通，峰值 RSS ≤ 1.5 GB（**已实测：27 s / RSS +9.6 MB，通过**）
- [ ] A2b ≥ 500 MB 跑通，峰值 RSS ≤ 1.5 GB（**未测，0.2.0 P8-1**）
- [ ] A3 中断后续跑，已完成部分不重翻
- [ ] A4 排版评分达标
- [ ] A5 干净 Win11 + 干净 macOS 安装并成功翻译样例
- [ ] A6 OCR 准确率：英文 ≥ 95%、中文 ≥ 92%
- [ ] 中文路径、空格路径、超长路径不崩
- [ ] 无 Ollama / 模型缺失 / 显存不足 三种异常均有明确引导而非崩溃
- [ ] 安装包体积 ≤ 400 MB（实测 Windows 156.5 MB / macOS dmg 187.0 MB，通过）
- [ ] 卸载后无残留（除用户数据目录，卸载时询问是否保留）
- [ ] SHA-256 校验值发布

## 8. 验收口径的版本切分（D10）

| 验收项 | 0.1.0 | 0.2.0 | 说明 |
|---|---|---|---|
| A1 离线零外发 | ✅ 必过 | — | 一票否决项 |
| A2a 页数维度 | ✅ 必过 | — | 已有实测数据（18 号 §4.1） |
| A2b 体积维度 | — | ✅ 必过 | ≥ 500 MB 样本从未构造，属 P8-1 |
| A3 断点续翻 | ✅ 必过 | — | 一票否决项 |
| A4 排版评分 | — | ✅ 必过 | 需 3 位评审，单人项目可降为「自评 + 1 位外部」 |
| A5 干净机安装 | ✅ 必过 | 复验 | 一票否决项；本机无法完成干净机验证，由 CI runner + 真实用户协助 |
| A6 OCR 准确率 | ✅ 必过 | — | 需先准备 300 dpi 中英各 10 页样本 |

> **为什么 A2 必须拆开**：0.1.0 若把「1000 页」和「500 MB」绑成一条，体积维度未测就意味着整条不通过、永远发不了版；而这两件事的风险来源完全不同（页数 = 状态累积；体积 = 单页复杂度与嵌入资源）。拆开后每个维度都能独立判定。
