# 07 · 构建、打包与发布方案

版本 v1.0 ｜ **本章是你最关心的交付环节，请重点确认**

## 0. 先说结论（三条硬事实）

1. **Windows `.exe` 安装包**：可以在你当前的 Windows 机器上直接构建，产物是一个 `LinguaForge-1.0.0-Setup.exe`（Inno Setup 制作，支持中文安装界面、开始菜单、卸载）。
2. **macOS `.dmg`**：**无法在 Windows 上交叉编译。** dmg 必须在 macOS 上生成（需要 `codesign`、`hdiutil`/`create-dmg`）。可行路径有三条，见 §3，推荐 **GitHub Actions 免费 macOS 构建**。
3. **两个架构**：Apple Silicon（arm64）与 Intel（x86_64）需分别构建；也可以只在 arm64 上构建（2019 年后的 Mac 全是 Apple Silicon），Intel Mac 用 Rosetta 2 运行 arm64 包是可行的降级方案。

## 1. Windows 构建流程

### 1.1 工具链
| 组件 | 用途 | 安装 |
|---|---|---|
| Python 3.12 | 运行时 | 官方安装器 |
| uv（推荐）或 pip | 依赖管理 | `winget install astral-sh.uv` |
| PyInstaller | 打包为 onedir | `uv pip install pyinstaller` |
| Inno Setup 6 | 制作安装程序 | https://jrsoftware.org/isdl.php（免费） |

> 选 **onedir**（一个目录 + 主 exe）而非 onefile：启动更快（不用每次解压几百 MB），增量更新也更方便，安装包负责把它整体装进 `Program Files`。

### 1.2 PyInstaller 要点
```python
# packaging/win/linguaforge.spec（要点摘要）
a = Analysis(
    ['app/main.py'],
    datas=[
        ('resources/fonts', 'resources/fonts'),
        ('resources/icons', 'resources/icons'),
        ('resources/ocr_models', 'resources/ocr_models'),   # RapidOCR ONNX
        ('resources/i18n', 'resources/i18n'),
    ],
    binaries=[],                      # onnxruntime 的 DLL 由 hook 自动收集
    hiddenimports=[
        'pypdfium2', 'pdfplumber', 'pypdf', 'reportlab',
        'rapidocr_onnxruntime', 'onnxruntime', 'cv2', 'PIL',
        'PySide6.QtCore','PySide6.QtGui','PySide6.QtWidgets',
    ],
    excludes=['torch','tensorflow','pandas','matplotlib','PySide6.QtWebEngine'],
)
```
- 用 `--noconsole`（GUI 模式），CLI 入口单独提供 `linguaforge-cli.exe`（console 模式）
- **必须排除**未用的 Qt 模块（QtWebEngine 有 100+ MB）
- 构建后用 `Dependencies` / 直接运行验证缺 DLL（常见坑：VC++ 运行库，可随安装包附带 `vc_redist.x64.exe`）

### 1.3 Inno Setup 安装包
```iss
#define MyAppName "LinguaForge"
#define MyAppVersion "1.0.0"
[Setup]
AppName={#MyAppName}
AppVersion={#MyAppVersion}
DefaultDirName={autopf}\LinguaForge
DefaultGroupName=LinguaForge
OutputBaseFilename=LinguaForge-1.0.0-Setup
Compression=lzma2/max
SolidCompression=yes
ArchitecturesAllowed=x64
Languages=ChineseSimplified,English      ; 中文安装界面
[Files]
Source: "dist\linguaforge\*"; DestDir: "{app}"; Flags: recursesubdirs
[Icons]
Name: "{group}\LinguaForge"; Filename: "{app}\linguaforge.exe"
Name: "{commondesktop}\LinguaForge"; Filename: "{app}\linguaforge.exe"; Tasks: desktopicon
[Tasks]
Name: "desktopicon"; Description: "创建桌面快捷方式"
[Run]
Filename: "{app}\linguaforge.exe"; Description: "启动 LinguaForge"; Flags: postinstall nowait skipifsilent
```
- 安装包体积预估：**280–400 MB**（PySide6 ~80 + onnxruntime ~45 + OpenCV ~30 + 字体子集 ~10 + OCR 模型 ~15 + 其余依赖）
- 如需瘦身：可用 Nuitka 编译（体积略小、启动更快，但构建时间以小时计）

### 1.4 签名（可选，决策 D6）
- 未签名：Windows SmartScreen 会提示"未知发布者"，用户点"更多信息 → 仍要运行"即可安装
- 已签名：OV 证书约 1000–3000 元/年，EV 更贵；签名后 SmartScreen 信誉需积累一段时间
- **建议 V1.0 先行未签名**，观察反馈再决定

## 2. macOS 构建流程

### 2.1 工具链
| 组件 | 用途 |
|---|---|
| Python 3.12（arm64） | 运行时 |
| PyInstaller | 生成 `.app` bundle（用 `--windowed`） |
| `create-dmg` 或 `dmgbuild` | 生成拖拽安装 dmg |
| `codesign` + `hdiutil` | 签名与打包（Xcode Command Line Tools 自带） |

### 2.2 生成 .app
```bash
pyinstaller packaging/mac/linguaforge.spec --noconfirm --clean
# 产物：dist/LinguaForge.app
```
spec 关键点：
- `BUNDLE` 段设置 `iconfile='resources/icons/app.icns'`、`bundle_identifier='com.linguadesk.LinguaForge'`
- 设置 `INFOPLIST_KEY_LSApplicationCategoryType`、最低系统版本 `LSMinimumSystemVersion = 12.0`
- **注意**：`--windowed`（.app）模式下 stdout 不可见，日志必须写文件
- Apple Silicon 上 `onnxruntime` 需要 `onnxruntime` 官方 wheel（支持 arm64），**不要**用 x86_64 wheel

### 2.3 生成 dmg
```bash
# 方案 A：create-dmg（推荐，自动做 Applications 快捷方式）
npm install -g create-dmg            # 或 brew install create-dmg
create-dmg \
  --volname "LinguaForge 1.0.0" \
  --volicon resources/icons/app.icns \
  --window-size 660 400 --icon-size 100 \
  --app-drop-link 480 170 \
  dist/LinguaForge.app

# 方案 B：dmgbuild（Python，配置可控）
dmgbuild -s packaging/mac/dmg_settings.py "LinguaForge" dist/LinguaForge-1.0.0.dmg
```

### 2.4 签名与公证（决策 D6）
```bash
# ad-hoc 签名（免费，至少避免"应用已损坏"）
codesign --deep --force --sign - dist/LinguaForge.app

# 正式签名（需 Apple Developer ID，99 USD/年）
codesign --deep --force --options runtime \
  --sign "Developer ID Application: Your Name (TEAMID)" dist/LinguaForge.app
# 然后 notarize（公证），否则首次打开仍会被 Gatekeeper 拦截
xcrun notarytool submit dist/LinguaForge-1.0.0.dmg --apple-id ... --team-id ... --wait
xcrun stapler staple dist/LinguaForge-1.0.0.dmg
```

| 状态 | 用户首次打开体验 |
|---|---|
| 未签名 / ad-hoc | 右键 → 打开，或系统设置 → 隐私与安全性 → 仍要打开 |
| 已签名已公证 | 双击直接打开，无警告 |
| 已签名未公证 | 有警告但可直接放行 |

**建议 V1.0**：ad-hoc 签名 + 在 README/下载页写清"右键打开"指引；若需要正式分发再买 Developer ID。

## 3. macOS dmg 的三条可行路径（决策 D5，请选一条）

| 方案 | 做法 | 优点 | 缺点 |
|---|---|---|---|
| **A. GitHub Actions（推荐）** ✅ | 仓库推 tag → `macos-latest`（arm64）自动构建 → 产出 dmg 上传 Release；你在网页下载 | 免费、可重复、无需 Mac、自动出双架构 | 仓库需公开或消耗 Actions 额度（私有仓库有免费额度）；首次配置约 1 小时 |
| B. 你在 Mac 上执行脚本 | 提供 `packaging/mac/build.sh`，你在 Mac 上跑一条命令 | 完全可控、可签名 | 你需要一台 Mac |
| C. 云端 Mac 租用 | MacinCloud / GitHub 大型 runner | 可交互调试 | 付费 |

**已确认方案：A · GitHub Actions 免费构建**（macOS dmg），Windows exe 安装包在本机 Windows 环境构建或同样走 Actions（`windows-latest`）。

配套动作（M0 阶段完成）：
1. 新建 GitHub 仓库（公开仓库 Actions 免费额度充足）
2. 提交 `.github/workflows/build.yml`（`build-windows` + `build-macos` 双 job）
3. 推送 `v*` tag 触发构建，产物上传 Release
4. V1.0 采用 ad-hoc 签名（`codesign --sign -`），README 与下载页写明 macOS"右键 → 打开"指引
5. 若后续需正式分发，再接入 Apple Developer ID 公证流程（§2.4）

工作流骨架：
```yaml
# .github/workflows/build.yml
jobs:
  build-macos:
    runs-on: macos-14            # Apple Silicon runner
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-python@v5
        with: { python-version: '3.12' }
      - run: pip install -r requirements.txt pyinstaller
      - run: pyinstaller packaging/mac/linguaforge.spec --noconfirm
      - run: codesign --deep --force --sign - dist/LinguaForge.app
      - run: npm i -g create-dmg && create-dmg ... || dmgbuild ...
      - uses: actions/upload-artifact@v4
        with: { name: macos-dmg, path: dist/*.dmg }
  build-windows:
    runs-on: windows-latest
    steps: [ ... pyinstaller + iscc ... ]
```
> 注：`macos-14` 及以后为 arm64 runner；如需 Intel 包，用 `macos-13`。

## 4. 版本与发布

| 项 | 约定 |
|---|---|
| 版本号 | 语义化 `MAJOR.MINOR.PATCH`，与 Git tag 一致 |
| 发布物 | `LinguaForge-1.0.0-Setup.exe`（Win x64）、`LinguaForge-1.0.0-arm64.dmg`（Mac Apple Silicon）、可选 `LinguaForge-1.0.0-x86_64.dmg` |
| 校验 | 每个发布物附 SHA-256 校验值 |
| 渠道 | GitHub Releases（推荐）；如需国内加速，可同步到网盘/镜像 |
| 更新 | 应用内仅"检查新版本"（请求 GitHub Release API），下载由用户手动完成；**不自动下载安装**（避免未签名被拦截的尴尬） |

## 6. 常见坑清单（提前规避）

| 坑 | 规避 |
|---|---|
| PyInstaller 漏收 onnxruntime DLL / Qt 插件 | 用 `hiddenimports` + 构建后真机运行验证；准备 `--collect-all` 兜底 |
| Windows 缺 VC++ 运行库 | 安装包内附带 `vc_redist.x64.exe` 静默安装 |
| macOS `onnxruntime` 架构不匹配 | CI 中明确 arm64 Python，禁止 x86 wheel |
| .app 内写文件失败（只读/沙箱） | 数据一律写到 `~/Library/Application Support/LinguaForge` |
| dmg 未签名被 Gatekeeper 拦截 | ad-hoc 签名 + 文档说明"右键打开" |
| 杀软误报（PyInstaller 常见） | 尽量用 onedir；正式版考虑签名；向厂商提交误报申诉 |
| 中文路径 / 空格路径崩溃 | 全链路使用 `pathlib`，CI 中加入中文路径用例 |
| 打包体积失控 | 排除 QtWebEngine、torch、pandas、matplotlib；字体子集化 |
