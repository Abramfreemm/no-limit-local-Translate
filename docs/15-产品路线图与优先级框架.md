## 2. 优先级框架

### 2.1 双框架并用

- **MoSCoW** 决定"这个版本要不要"（Must / Should / Could / Won't）
- **RICE** 决定"同一档内先做哪个"

RICE = (Reach × Impact × Confidence) / Effort

| 因子 | 口径（本产品） |
|---|---|
| Reach | 受影响用户占比（0–100，%）。离线工具无遥测，按"目标画像中会遇到该场景的比例"估 |
| Impact | 3 = 决定性（不做就不能用）；2 = 显著（影响留存）；1 = 轻微（体验加分）；0.5 = 几乎无感 |
| Confidence | 100% = 已实测；80% = 有明确证据；50% = 合理推测 |
| Effort | 人日（单人） |

### 2.2 打分表（节选关键项）

| 需求 | 来源 | Reach | Impact | Conf | Effort | RICE | 档位 |
|---|---|---|---|---|---|---|---|
| 错误码体系与用户可读错误 | 13 §6 / 19 | 95 | 3 | 100% | 3 | **95.0** | Must |
| 开始前预检查（磁盘/权限/加密/模型） | 13 §5.2 | 60 | 3 | 100% | 2 | **90.0** | Must |
| 断点续翻（已有，需修健壮性） | FR-6.3 | 40 | 3 | 90% | 3 | 36.0 | Must |
| 内存护栏 + 1000 页压测 | FR-6.6 / A2 | 25 | 3 | 100% | 4 | 18.8 | Must |
| 术语冲突处理 | FR-4.6 | 20 | 2 | 100% | 2 | 20.0 | Should |

### 2.3 一票否决项（Veto，不看 RICE）

以下任一项不满足，**V1.0 不发版**：

1. A1 断网全流程可用（零外发）
2. A2a 1000 页跑通（0.1.0）+ A2b ≥ 500 MB 跑通（0.2.0），峰值 RSS 均 ≤ 1.5 GB
3. A3 断点续翻有效
4. A5 干净 Win11 与干净 macOS 能装上并成功翻译
5. 安装包内 `THIRD_PARTY_LICENSES.txt` 与 OFL 全文齐备
6. 无 AGPL/GPL/NC 依赖进入分发产物

## 4. 明确砍掉的东西与理由

砍功能比加功能更需要理由，逐条写清。

### 4.1 EPUB（FR-1.5，P1 → Won't）

**理由**：RICE 0.8，投入 5 人日只覆盖 8% 的画像。EPUB 本质是 zip+OPF+XHTML，解析不难，但**写出**保结构很难（CSS、章节、脚注、目录重排），做不好比不做更伤口碑。
**替代**：EPUB 用户的真实诉求是"读整本书"，把 EPUB 转成 HTML 后用 HTML 通道处理即可，不单独做。

### 4.2 ODT / RTF（FR-1.7，P2 → Won't）

**理由**：`02` 原文写"经 LibreOffice 转换"，这与 `03` 的选型原则"不依赖外部可执行程序"直接冲突。要么引入外部依赖破坏离线一致性，要么自研解析器陷入维护泥潭。ROI 极低。

### 4.3 自动更新检查（FR-7.5 → 降级为 Could，且默认关闭）

**理由**：这是唯一需要联网的功能，而产品的**第一卖点是零外发**。一个"检查更新"请求会暴露 IP、版本、时间，并与"绝不上传"的承诺在用户心里打架。
**替代**：不做请求，改为「关于」页放一个 GitHub Releases 链接，用户自己点。零代码成本，零隐私妥协。

### 4.4 PaddleOCR / VLM OCR（FR-3.5 → Won't）

**理由**：PaddleOCR 需要按需下载大模型，破坏"装上就能用"；VLM OCR 一页数十秒，与"900 页手册"的场景直接矛盾。RapidOCR 的精度对本产品的目标是够的（目标不是出版级，是"能读 + 能搜"）。
**保留**：`OcrEngine` 抽象接口保留，第三方可自行接入（这也是 Apache-2.0 许可的价值之一）。

### 4.5 云端翻译后端（始终 Won't）

**理由**：一旦支持 DeepL/Google API，"不上传"的定位就死了。这是产品身份问题，不是功能取舍。

## 5. 技术债偿还排期

技术债不是"以后再说"，要排进版本。

| # | 债务 | 影响 | 偿还版本 | 预估 |
|---|---|---|---|---|
| T1 | 无错误码，异常裸抛 `str(e)` 到 UI | 用户看不懂、无法归类、无法统计 | **V1.0** | 3 人日 |
| T2 | `TMConfig.min_match_ratio` 是死配置 | 配置项说谎，用户调了没反应 | **V1.0** | 0.5 人日（删除或实现） |
| T3 | `fallback_models` 含本机已删除的 `qwen3:8b` | 降级链实际只有一跳 | **V1.0** | 0.5 人日 |
| T4 | `translator._call()` 硬编码 `time.sleep` | 单测无法跑重试路径（12 号 §1.3#1） | **V1.0** | 1 人日 |
| T5 | `OllamaClient` 无法注入 transport | HTTP 错误码无法单测 | V1.1 | 1 人日 |
| T6 | UI 与 `pipeline` 能力常量重复定义（已部分修） | 能力漂移 | 已修 | — |
| T7 | watcher/UI 三处各写一套进度格式化 | 文案不一致 | V1.1 | 1 人日 |
| T8 | 无 schema_version 迁移机制 | V1.1 改表会毁用户数据 | V1.1 | 2 人日 |

**规则**：每个版本至少偿还 2 项债务，否则技术债表只增不减。

## 6. 交付门禁（DoR / DoD）

### 6.1 DoR（Definition of Ready，开工前）

一个需求进入开发前必须满足：

- [ ] 在 `02` 或 `13` 里有编号（FR-x 或 PRD 章节）
- [ ] 有明确的验收方式（可测）
- [ ] 依赖已就绪（如：需要的模型已确认可拉到）
- [ ] 已评估对"零外发"与"许可"两条红线的影响

### 6.2 DoD（Definition of Done，收工前）

- [ ] 代码通过 `ruff` + 单测（新增逻辑有对应用例）
- [ ] 在干净环境跑通一次真实样本
- [ ] 错误路径有可读文案（符合 13 §6 三段式）
- [ ] 相关文档已更新（本套 00–21 中受影响的章节）
- [ ] 没有引入新的技术债（或已登记进 §5）

## 7. 触发条件（什么情况下改计划）

计划不是死的，但改要有触发条件，不能凭心情。

| 触发条件 | 应对 |
|---|---|
| 1000 页压测峰值 RSS > 2 GB | 暂停新功能，先做内存护栏（M-6 升为唯一优先级） |
| pdf2zh 变更许可为宽松 | 14 号 §3 的三个空白失效一个，加速"多格式"（M-3）投入 |
| 真实用户反馈中排版问题占比 > 40% | 重新评估是否引入版面检测模型（需评估许可与体积） |
| macOS CI 构建持续失败 | 降级为"仅 Windows 发布 + 源码开放，Mac 用户自行构建"，并在 README 明示 |
| Ollama API 破坏性变更 | 冻结发布，先修兼容层；不允许"让用户降级 Ollama" |
