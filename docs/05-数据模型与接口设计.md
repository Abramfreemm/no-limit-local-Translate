# 05 · 数据模型与接口设计

版本 v1.0

## 1. DocIR（文档统一中间表示）

### 1.1 设计目标
- 能表达"页面 / 块 / 行 / 样式 / 资源"五级结构
- 同时承载原文与译文，并保留坐标（PDF 回填需要）
- 可 JSON 序列化、可增量落库（按块存储，不整文档读写）
- 与具体格式无关

### 1.2 Schema（v1.0）

```jsonc
{
  "schema": "DocIR/1.0",
  "doc_id": "sha256:ab12...",
  "source": {
    "path": "D:/docs/paper.pdf",
    "format": "pdf",              // pdf|docx|pptx|xlsx|epub|html|md|txt|srt|vtt|image|csv|odt
    "size_bytes": 123456789,
    "page_count": 128,
    "title": "...",
    "lang": "en"
  },
  "page_spec": [                   // 页面尺寸（pt），PDF 必需
    { "index": 0, "width": 595.28, "height": 841.89, "rotation": 0 }
  ],
  "blocks": [
    {
      "id": "b-000123",            // 全局唯一，稳定（同文件重开一致）
      "page": 12,                  // 无页概念的格式填 0，用 seq 排序
      "seq": 47,                   // 阅读顺序
      "type": "paragraph",         // heading|paragraph|list_item|table_cell|caption|
                                   // formula|code|image|header|footer|footnote|note
      "bbox": [72.0, 640.1, 523.3, 702.4],   // [x0,y0,x1,y1]，PDF 用 pt，左上原点
      "text": "The measured efficiency ...",
      "runs": [                    // 富文本样式（可选，Writer 按需使用）
        { "offset": 0, "len": 20, "font": "Times-Bold", "size": 10.5,
          "color": "#000000", "bold": true, "italic": false }
      ],
      "style": { "align": "justify", "line_spacing": 1.15, "space_before": 6,
                 "dir": "ltr", "column": 0 },
      "translatable": true,
      "translated": "实测效率……",
      "state": "pending",          // pending|done|failed|skipped|cached
      "origin": "text_layer",      // text_layer|ocr|extract
      "confidence": 0.96,          // OCR 置信度，文本层为 1.0
      "meta": { "font_size_median": 10.5, "glossary_hits": ["efficiency"] }
    }
  ],
  "assets": [                      // 图片 / 表格 / 字体等不可翻译资源
    { "id": "a-001", "page": 12, "bbox": [72,300,523,600],
      "kind": "image", "path": "cache/ab12/p12_a001.png",
      "keep": true }
  ],
  "outline": [                     // 目录 / 书签 / 章节
    { "title": "3. Methodology", "page": 12, "level": 1 }
  ]
}
```

**存储策略**：`blocks` 不整体存为一个 JSON，而是**一行一块**写入 SQLite（见 §3），避免大文档内存膨胀，并支持按页增量更新。

## 2. Ollama 接口契约

### 2.1 探测与模型发现
```
GET  http://127.0.0.1:11434/api/tags
→ { "models": [ { "name":"translategemma:12b", "size":8100000000,
                  "details": {"parameter_size":"12b","family":"gemma3"} } ] }

GET  http://127.0.0.1:11434/api/version         # 连通性探测（超时 2s）
POST http://127.0.0.1:11434/api/show            # 查单个模型 context length 等
GET  http://127.0.0.1:11434/api/ps              # 已加载模型与显存占用
```

### 2.2 翻译请求（核心）
```
POST http://127.0.0.1:11434/api/chat
{
  "model": "translategemma:12b",
  "stream": false,
  "keep_alive": "30m",
  "format": "json",                    // 强制结构化输出
  "options": { "temperature": 0.15, "top_p": 0.9, "num_ctx": 8192,
               "num_predict": 2048, "repeat_penalty": 1.05 },
  "messages": [
    { "role": "system", "content": "<SYSTEM_PROMPT>" },
    { "role": "user",   "content": "<PAYLOAD>" }
  ]
}
→ { "message": { "content": "{\"translations\":[\"...\",\"...\"]}" },
    "prompt_eval_count": 120, "eval_count": 340, "total_duration": 3.2e9 }
```

### 2.3 Payload 契约（保证条数对齐的关键）

发给模型的用户输入采用**编号 + JSON 输入**：

```json
{
  "task": "Translate each item from en to zh-Hans.",
  "glossary": [ { "src": "transformer", "dst": "变换器", "note": "" } ],
  "context": "...(上一段原文与译文，用于术语与语气一致)...",
  "items": [
    { "id": 1, "text": "We propose a novel ..." },
    { "id": 2, "text": "Figure 3 shows ..." },
    { "id": 3, "text": "In contrast, ..." }
  ],
  "output": "Return JSON: {\"translations\":[{\"id\":1,\"text\":\"...\"}]}. Keep the same count and order. Do not merge or split items. Do not add explanations."
}
```

**校验与降级链**：
```
解析 JSON 失败 → 去掉 format:"json" 重试一次
条数不匹配     → 按 id 对齐；缺项标记 failed
仍失败         → 批次折半，递归重试（最多 2 层）
仍失败         → 逐条翻译（兜底）
逐条仍失败     → 标记 failed，保留原文，UI 高亮
```

### 2.4 模型下载
```
POST http://127.0.0.1:11434/api/pull   { "name":"translategemma:12b", "stream":true }
→ 逐行 {"status":"pulling manifest","total":...,"completed":...}
→ UI 显示百分比与速度
```

### 2.5 错误处理约定
| 情况 | 处理 |
|---|---|
| 连接被拒 / 超时 | 判定 Ollama 未启动 → 弹引导（含一键打开 ollama.com 下载页） |
| 404 model not found | 提示并提供一键拉取按钮 |
| 500 / 显存不足 | 建议更小模型或降低 `num_ctx`，提供"切换到 4b"快捷操作 |
| 响应超长被截断 | 减少批次大小后重试 |

## 3. 存储设计（SQLite）

位置：`platformdirs.user_data_dir("LinguaForge")/linguaforge.db`，WAL 模式。

```sql
-- 任务
CREATE TABLE task (
  id            TEXT PRIMARY KEY,       -- uuid
  source_path   TEXT NOT NULL,
  source_sha256 TEXT,                   -- 用于翻译记忆与续翻匹配
  source_format TEXT,
  page_count    INTEGER,
  src_lang TEXT, dst_lang TEXT,
  model TEXT, output_mode TEXT,         -- mono|dual|md|docx|...
  status TEXT,                          -- queued|running|paused|done|failed|canceled
  created_at REAL, updated_at REAL,
  settings_json TEXT
);

-- 页（流式落盘的最小单位）
CREATE TABLE page (
  task_id TEXT, page_index INTEGER,
  width REAL, height REAL,
  need_ocr INTEGER, status TEXT,        -- pending|ocr_done|translated|rendered
  ocr_ms INTEGER, error TEXT,
  PRIMARY KEY (task_id, page_index)
);

-- 文本块（DocIR block 一行一块）
CREATE TABLE block (
  task_id TEXT, block_id TEXT,
  page_index INTEGER, seq INTEGER, type TEXT,
  bbox_json TEXT, text TEXT, translated TEXT,
  style_json TEXT, translatable INTEGER,
  state TEXT, origin TEXT, confidence REAL,
  PRIMARY KEY (task_id, block_id)
);
CREATE INDEX idx_block_task_page ON block(task_id, page_index);
CREATE INDEX idx_block_state ON block(task_id, state);

-- 翻译记忆（跨任务复用，命中即不调用模型）
CREATE TABLE translation_memory (
  src_lang TEXT, dst_lang TEXT, model TEXT,
  src_hash TEXT,                        -- sha256(归一化原文)
  src_text TEXT, dst_text TEXT,
  hit_count INTEGER, created_at REAL,
  PRIMARY KEY (src_lang, dst_lang, model, src_hash)
);

-- 术语表
CREATE TABLE glossary (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  src_lang TEXT, dst_lang TEXT,
  term TEXT, translation TEXT,
  case_sensitive INTEGER DEFAULT 0,
  do_not_translate INTEGER DEFAULT 0,
  note TEXT
);

-- 设置
CREATE TABLE setting (key TEXT PRIMARY KEY, value TEXT);
```

## 4. 任务状态机

```
        ┌──────────────── cancel ────────────┐
        ↓                                    │
  queued ──start──> running ──pause──> paused ──resume──> running
                      │  │                                   │
                      │  └──── error ──> failed ──retry──────┘
                      └──── 全部页 rendered ──> done
```

- **断点恢复**：重启后扫描 `status='running'|'paused'` 的任务，按 `page.status` 与 `block.state` 定位续跑起点。
- **取消**：置 `canceled`，删除临时文件，保留已译内容以便"从此处重跑"。

## 5. 内部接口签名（编码时遵循）

```python
# core/parsers/base.py
class BaseParser(Protocol):
    def supports(self, path: Path) -> bool: ...
    def parse(self, path: Path, ctx: PipelineContext) -> Iterator[DocIRChunk]: ...
    # 以生成器逐页产出，保证流式

# core/ocr/base.py
class OcrEngine(Protocol):
    name: str
    def recognize(self, image: np.ndarray, lang: str) -> list[OcrLine]: ...
# OcrLine = {text, bbox(4点), confidence}

# core/translate/base.py
class Translator(Protocol):
    def translate_batch(self, items: list[BatchItem], src, dst) -> list[TranslatedItem]: ...

# core/writers/base.py
class BaseWriter(Protocol):
    def write(self, ir_reader: DocIRReader, out_path: Path, mode: str) -> Path: ...
```

## 7. v2 契约变更预告（0.1.0 落地）

| 变更 | 现状 | 目标 | 归属 |
|---|---|---|---|
| `PipelineResult.errors` | `list[str]`（中文拼接，如 `f"打开失败: {e}"`） | `list[Problem]`（`code` + `severity` + `params`） | P1-3 |
| 解析异常 | 6 个 `*ParseError` 各自独立 | 统一 `DocumentParseError(format, problem)` | P1-2 |
| `TranslationMemory` 配置 | `TMConfig.min_match_ratio` 为死配置（只做精确匹配） | **删除该字段**，不留"将来会实现"的假接口 | P1-1 顺手清理 |
| `OutputConfig.fmt` 注释 | 写作 `markdown \| txt \| bilingual`，但 `bilingual` 从不是 `fmt` 取值 | 更正为 `markdown \| text \| pdf \| docx \| pptx \| xlsx \| srt`，双语由独立布尔位 `bilingual` 控制 | P1-1 |

> 这些都是**跨模块契约**，改动必然波及 CLI/UI/测试三方。做法是一次改完、全量跑测，不设兼容层（理由见 21 号 §10）。
